# 0.1.1：修复所有页面显示网络请求失败

日期：2026-09-14

## 现象与原因

用户安装0.1.0后能识别31页，但保存时每页都显示网络请求失败。在本机独立浏览器页面中，用真实浏览器fetch读取同一张本地PNG：直接调用成功（248,605字节，1023×1447），通过0.1.0任务对象的默认fetcher调用则报 `TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation`。

`this.fetcher = fetch` 随后 `this.fetcher(...)` 将原生接口的this改成了任务对象。请求尚未发出即失败，被旧版统一映射为网络/权限错误。Node环境和使用箭头函数的模拟fetch未体现该浏览器限制。

## 修复

- 默认请求函数使用 `globalThis.fetch.bind(globalThis)`；请求地址范围、重定向限制、登录会话、超时和并发保持原策略。
- 调用对象异常显示为扩展调用错误，避免误导用户排查网络权限。
- 模拟fetch也检查调用对象；新增不覆盖原生fetch的独立浏览器检查页。
- 自动测试新增默认函数调用对象回归及错误提示区分。回归用例在旧代码下失败，修复后22/22自动测试通过。
- 版本更新为0.1.1；构建路径跟随版本。已安装的0.1.0目录保留地址并更新文件，用户只需重新加载扩展。

## 修复后验证

- 原生浏览器复测通过：直接请求和修复后任务的默认请求均读取248,605字节PNG，解码尺寸均为1023×1447；不覆盖原生fetch。
- 使用更新后的模拟fetch运行完整界面流程，31/31页导出完成；产物5,166,012字节。
- 用Python重新解析这份PDF，31页的每张内嵌图片均与原PNG像素相同，顺序正确。报告为 `work/regression-0.1.1/simulation-validation.json`。
- 已构建0.1.1并同步更新本机原安装目录；修复前engine备份在 `work/regression-0.1.1/engine-before-fix.js`。
- 真实Edge重新加载后保存仍待用户反馈。安装管理页与扩展页面受浏览器工具URL策略限制，实际重新加载与保存由用户操作；不把本地模拟结果记为真实扩展下载成功。

参考：[MDN 对不兼容 this 调用的说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Errors/Called_on_incompatible_type)。具体原因已通过本机浏览器复现确认。
