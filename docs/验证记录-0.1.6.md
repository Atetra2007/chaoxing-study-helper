# 0.1.6低内存保存验证记录

日期：2026-09-18。目录：`项目根目录`。版本：0.1.6，本地开发构建。

## 实现与完整性

- 图片获取仍为默认3并发，每页校验内容、尺寸、哈希后写入OPFS，写入成功才计为已获取。内存Map保留页码/尺寸/长度/哈希，不保留图片字节；并发磁盘写入有总量预留，失败退回预留额度。
- PDF按数字页码构建，每次只创建一页pdf-lib文档，将该页对象和资源写入临时文件后从目标上下文删除。页树、对象偏移量与仍待复用的重复资源引用保留在内存；不保留全书图片/字体流。重复页共享资源，保留独立页面和重复提示。
- 图片压缩仍用既有`preparePDFImage`；OCR仍使用既有本机接口、页数/比例校验及图片回退，不改变识别分类。重复文字页复用资源且不重复调用OCR。
- PDF使用普通xref表，结尾写页树、元数据、xref与trailer。核对对象长度、引用偏移完整性；文件关闭提交后，每次最多1MiB回读核对SHA-256，再读取小型页树核对页数及页引用顺序、核对文件总长度。不会为校验重新解析整份PDF到内存。
- 下载直接使用OPFS的File对象及Blob URL；只有浏览器报告下载完成才显示成功。记录直接使用写入时计算、回读确认的内容哈希，不再读取全文件。下载结束释放Blob URL。
- 相同会话失败时保留来源图片，删除未完成输出；再次合并可重新选择画质或OCR。缓存读取长度/哈希不符会将对应页标为失败并重新获取。成功、取消、换资料和重新识别清理本次存储；取消等待全部在途请求和写入结束。
- 每任务随机目录及Web Lock防止同源助手误删彼此数据，锁释放后允许下一次保存清理异常关闭遗留目录。只清理专用命名空间，不触碰下载文件。存储失败明确停止，无全量内存回退。
- 单页25MiB、图片总量250MiB、500页限制不扩大。磁盘需容纳来源、输出及浏览器临时写入副本；单张超大图片的解码仍可能有较高瞬时内存，不承诺固定浏览器总内存上限。

## 接口依据

- [OPFS根目录API](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/getDirectory)。
- [createWritable提交与关闭语义](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)：写入关闭后才以文件读取已提交内容。
- [noble-hashes增量哈希实现](https://github.com/paulmillr/noble-hashes)；本项目固定版本并随构建分发。
- PDF对象复制和序列化行为以本地固定pdf-lib 1.17.1源码及上述结构/渲染回归为依据；升级该库须复验写入器。
