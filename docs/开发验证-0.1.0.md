# 0.1.0 开发与验证记录

日期：2026-09-14

## 实现

Manifest V3扩展。工具栏入口打开独立的扩展保存标签页，页面按需调用 `chrome.scripting.executeScript`，读取当前课件及各嵌套框架的可见下载链接和分页图片DOM。脚本不改变课件，不读取浏览器Cookie或页面隐藏应用状态。

图片获取限并发3，单页超时20秒，自动尝试最多3次。成功页面保留在内存中；暂停不发新请求，重试只补失败页。单页25MB、总图片量250MB、总页数500限制用于避免失控内存占用。

任务固定资料身份和页码列表，下载前及PDF生成前重新核对原文档。原文档被关闭或替换时不继续宣称完整成功。

PDF由本地打包的pdf-lib生成；数字排序后逐页嵌入图片，重新解析检查页数。只有 `chrome.downloads` 返回完成状态后才显示成功。同名文件使用 `conflictAction: uniquify`。

- 恢复网络后重试：从30/31继续，补第7页后完成导出。
- 慢网络界面测试：暂停后保持3/31页，继续可恢复；取消后解除输入锁定，不显示保存成功。
- 产出的31页PDF均含内嵌图片；Python逐页核对与原PNG像素一致，页序正确。
- 抽查第15页PDF渲染，正文公式可读，无新增裁切。

## 真实页面核对

在用户重新打开的Edge课件上，通过浏览器只读DOM操作复核识别逻辑：标题“附件：第一章教材”；内层阅读器匹配 `screen/v2`，读取31页连续页码及31张已加载的1023×1447 PNG；顶层未发现可见原文件链接。

这项核对不等于已安装扩展的端到端测试。
