# 0.2.1：小窗无法识别的启动修复

日期：2026-10-14。

## 现象与原因

用户反馈课件页面正常、小窗出现，但无法识别，提示“保存遇到未分类错误”。本轮在Edge读到已打开的第5章课件阅读器，DOM中列出9页，说明课件内容本身已加载；未将页面可见等同于扩展已识别。

确定的代码缺陷：0.2.0的 `offscreen.js` 顶层执行 `chrome.runtime.getManifest().version`。Chromium对offscreen的runtime方法有单独白名单，`getManifest`不在其中；此处会在注册消息监听之前抛错，识别命令因此无法接入任务宿主。普通网页合成预览提供了完整模拟runtime，之前136项测试未覆盖这一限制。

依据：Chromium [API功能白名单](https://raw.githubusercontent.com/chromium/chromium/140.0.7339.0/extensions/common/api/_api_features.json)中 `runtime.getManifest` 未包含 `offscreen_extension`，`runtime.getURL/id/onMessage/sendMessage`允许该上下文。同步核对当前Chromium实现一致。

已排除的猜测：扫描函数序列化不依赖外部模块；新旧阅读器、WPS和资料库夹具结果一致。Chromium允许allFrames跳过单个不可注入子框架，没有依据为此新增权限或改写扫描器。

## 修复

- 仅在service worker读取manifest版本，通过受信后台命令的独立version字段传给任务宿主；网页payload不能覆盖。
- offscreen启动只调用允许的方法，不再使用getManifest。
- 后台启动/连接失败提供明确恢复操作；初始化失败也能复制包含版本、阶段和安全分类的诊断，不展示原始异常或资源链接。
- 尚未建立来源绑定时，“重新识别”重新执行初始化；延迟到达的普通进度消息不会清空当前连接错误。
- 版本更新为0.2.1；无新增权限或网站范围。

## 验证

- `pnpm test`：145/145通过，0失败、0跳过。
- 新增受限运行环境执行生产offscreen代码和真实TaskSession，只提供允许的runtime成员。重插0.2.0的旧启动语句会在消息监听注册前报 `getManifest is not a function`；新实现可扫描到ready，诊断版本为0.2.1。
- 验证背景版本传递、拒绝不受信来源、启动诊断、初始化失败后重试恢复、后到状态保留连接错误和敏感原始异常不泄露。
- 本轮未改OCR推理、图像处理或PDF写入逻辑，因此未重跑整本教材或OCR模型。
- 构建及 `pnpm update:local` 成功，36个文件校验后写入固定目录 `outputs/chaoxing-study-helper-0.1.0`，内部manifest为0.2.1。旧文件备份位于 `work/extension-backups/2026-10-14T14-03-03-992Z-8067b035`。

上述回归是代码与受限API模型验证，不替代真实Edge。浏览器工具禁止访问 `edge://extensions`，由用户手动完成扩展重载和课件刷新。
